# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A "상식 퀴즈 게임" (general-knowledge quiz) web app. Stages 1–3 are done: seed data, the game API, the play flow, the leaderboard, the nickname filter and server-side anti-cheat. Stage 4 added game modes, the difficulty-based scoring and hints. README.md is the user-facing guide, in Korean. It covers commands, scoring rules, how to add questions, and the API table.

Stack: Next.js 16 (App Router, Turbopack), React 19, TypeScript, Tailwind CSS 4 (`@import "tailwindcss"` in `globals.css`, no config file), SQLite via `better-sqlite3`, Vitest. `AGENTS.md` is generated by `next dev` and says to check `node_modules/next/dist/docs/` before relying on remembered Next.js APIs. For example, `searchParams` in a page is a `Promise`.

## Commands

```bash
npm run validate-questions   # check src/data/questions.json
npm run seed                 # validate, then upsert questions into data/quiz.db
npm run dev                  # dev server
npm test                     # all tests (unit + API integration), in-memory DB
npx vitest run src/lib/scoring.test.ts   # one file
npx vitest run -t "comboBonus"           # by test name
npm run lint                 # tsc --noEmit (no ESLint is set up)
npm run build
npm run build:html           # regenerate the standalone index.html (see below)
```

`QUIZ_DB_PATH` overrides the DB file. Point it at a scratch file when you run a dev server for manual or browser testing, so test games don't land on the real leaderboard.

npm 11 blocks install scripts unless they are allowed in `package.json` → `allowScripts`. `better-sqlite3` (native build) and `esbuild` (used by tsx and vitest) are on that list. If a version bump drops them, `better-sqlite3` fails to load. Fix it with `npm install-scripts approve <pkg>` and then `npm rebuild <pkg>`.

`next dev` starts a detached `start-server.js` process. Stopping the npm wrapper leaves that process alive, and a second `next dev` then refuses to start. Kill the PID that the error message prints.

## Architecture

- **Modes** are defined in `MODES` in `constants.ts`: `challenge` (40 questions, 10 from each category, mixed, 20 s), `category` (10 from one category, 20 s) and `speed` (20 from all, 15 s). Read the question count and time limit from `MODES[session.mode]`, never from a global constant. Mixed modes store `sessions.category = 'random'`.
- **Scoring** (`scoring.ts`): a correct answer earns `10 × difficulty multiplier` (1/1.5/2), +3 if under 10 s, +2 if no hint was used, and a combo bonus on every correct answer in a streak (3–4: +2, 5–9: +5, 10+: +10). A miss or timeout scores 0 and resets the combo. `maxGameScore` takes the list of dealt difficulties.
- **Hints.** Every question has a `hint`. `revealHint` (`POST /api/game/hint`) returns it only for the revealed, unanswered question and sets `session_questions.hint_used_at`. `submitAnswer` reads that column to drop the no-hint bonus. A re-requested question comes back with `hint` filled in if it was already used.
- **The server is the source of truth.** Game rules live in `src/lib/game.ts` (`startGame`, `nextQuestion`, `submitAnswer`, `finishGame`), and the leaderboard lives in `src/lib/leaderboard.ts`. Each function takes a `DB` as its first argument so tests can pass `openDb(":memory:")`. Route handlers in `src/app/api/**/route.ts` are thin wrappers. They use `handleJson` for POST and `respond` for GET, both in `src/lib/api.ts`, which map `GameError(status, code)` to an HTTP response.
- **Questions are revealed one at a time.** `startGame` deals all of the mode's questions into `session_questions` but returns only the first. The client calls `/api/game/next` after each feedback. The first request for a question sets `session_questions.revealed_at` (epoch ms), and asking again returns the same question with less time left.
- **Timing is checked on the server.** In `submitAnswer`, the time actually used is `min(limit, max(clientMs, serverElapsed − LATENCY_ALLOWANCE_MS))`, where `limit` is the mode's time limit. A client can't claim an instant answer, and an answer that arrives late counts as a timeout. A client time outside 0–limit gets a 400. Answers must also arrive in order, must be for a revealed question, can be submitted only once, and are capped at the mode's question count. Sessions past `SESSION_TTL_MS` (30 min) return 410. `finishGame` re-checks the score against `MAX_SCORE_PER_ANSWER` and `maxGameScore()`.
- **The client never sees the answer index.** Choices are shuffled per session. `choice_order[shownIndex] = originalIndex`. `answers.selected_index` stores the **original** index, with `NULL` meaning a timeout. `AnswerResult.correctIndex` is in the **shown** order.
- **Leaderboard.** There is no leaderboard table. `leaderboard.ts` ranks `sessions WHERE finished_at IS NOT NULL` with `ROW_NUMBER() OVER (total_score DESC, correct_count DESC, finished_at ASC, id ASC)`. There are six boards (`LEADERBOARD_BOARDS`): `challenge`, `speed`, and one per category for category mode. `boardFor(mode, category)` maps a game to its board. Sessions with `mode IS NULL` come from before modes existed, were scored on the old 100-point scale, and appear on no board. Abandoned games never get `finished_at`, because `finishGame` requires every answer. `finishGame` returns the single `rank` on the game's board.
- **"My" leaderboard row** is the browser's last finished session, stored in localStorage as `quiz.lastSessionId` (see `lastSession` in `client-api.ts`). It is passed as `?sessionId=` and comes back as `isMine`. If it ranks below the top 50, it comes back separately as `me`.
- **Nicknames.** `src/lib/nickname.ts` (`validateNickname`) is shared by the start screen and `startGame`. It wraps `src/lib/profanity.ts`, which matches `src/data/banned-words.json` against several normalized variants of the input (leet-mapped, digits dropped, Hangul-only). When you add words, check for false positives in `nickname.test.ts`. That is why `시바` isn't on the list: it would block `시바견`.
- **Server/client boundary.** `db.ts`, `game.ts`, `leaderboard.ts`, `seed.ts` and `api.ts` are server-only. Client components (`src/components/*`, all `"use client"`) may import only from `constants.ts`, `scoring.ts`, `nickname.ts`, `profanity.ts`, `client-api.ts`, and the type-only `types.ts`. `next.config.ts` lists `better-sqlite3` under `serverExternalPackages`.
- **Schema.** `src/lib/db.ts` runs `migrate()` and then `CREATE TABLE/INDEX IF NOT EXISTS` on every open. When you add a column, add an `ALTER TABLE` to `migrate()`, the way `revealed_at`, `hint_used_at`, `questions.hint` and `sessions.mode` were added, so existing `data/quiz.db` files keep working. `getDb()` caches the connection on `globalThis` so dev hot reloads reuse it.
- **UI.** `/` is a single client state machine (`QuizApp`: start → mode → quiz → result; `ModeScreen` picks the mode, and the category in category mode). `/leaderboard` is a separate route. The server page reads `?board=` (default `challenge`), and `LeaderboardView` fetches the data and keeps the URL in sync with the selected tab. In `QuizScreen`, the timer and key handler read refs (`lockedRef`, `phaseRef`) so a choice can't be submitted twice. Feedback auto-advances after 2 s.
- **Accessibility conventions.** `globals.css` gives every element a global `:focus-visible` outline, so don't add `outline-none` to interactive elements. Small text uses `slate-600` or darker for contrast. State is never shown by color alone: there are ✓/✗ icons and text tags. Decorative emoji get `aria-hidden`. The leaderboard tabs follow the WAI-ARIA tabs pattern, with arrow keys, Home and End.

## Standalone index.html

The user's main way to play is to double-click `index.html` in the project root. It is a **generated** file, so don't edit it by hand. `scripts/build-standalone.ts` uses esbuild to bundle `src/standalone/main.ts` into one IIFE, then inlines that bundle and `style.css` into `template.html`. The page has no server: questions come from the bundled `questions.json`, and records live in localStorage (`quiz.records`, `quiz.lastRecordId`), so it has no server-side anti-cheat.

It is a vanilla-DOM app and shares no UI code with the React app. It reuses `constants.ts`, `scoring.ts`, `nickname.ts`/`profanity.ts`, and `ranking.ts`, which is the leaderboard boards and order as a pure function and must stay in sync with the SQL in `leaderboard.ts`. Records saved before modes existed have no `mode` and are left off every board. When a game rule or a question changes, update both apps and run `npm run build:html`. Verify by opening it via `file://`.

## Question data

`src/data/questions.json` is the source of truth. Edit it, then run `npm run seed` and `npm run build:html`. Seeding upserts by `id` and marks questions that are missing from the file as `retired`. It never deletes them, because past answers reference them. `src/lib/question-validation.ts` enforces the rules, and `seed` refuses to run on invalid data:

- At least 20 active questions per category, with a difficulty mix of 30% easy (1), 50% medium (2) and 20% hard (3), ±5 percentage points, per category
- Exactly 4 distinct, non-empty choices, `answer_index` in 0–3, and no duplicate ids or question text (compared without whitespace or punctuation)
- A non-empty, single-line `explanation` and `hint`; the hint must not contain the correct answer (answers of two or more characters are checked)

Content rules that validation can't check: each question needs exactly one unambiguous answer, and no facts that change over time. A hint should help without giving the answer away, and is held to the same fact-checking rules as the explanation. Korean text relies on `word-break: keep-all` in `globals.css`.

## 퀴즈 문제 교차 검증 가이드라인

모든 문제를 작성할 때 확인할 사항:

1. 정답이 하나뿐인가?
   - 다른 해석이 가능하면 조건을 명시한다 (예: 면적 기준, 해발 고도 기준).
2. 최상급 표현에 기준이 있는가?
   - '가장 큰', '최초의' 등의 표현에는 측정 기준을 명시한다.
3. 시간과 범위가 명확한가?
   - 시간이 지나 바뀔 수 있는 정보(현직자, 기록, 인구, 순위 등)는 출제하지 않는다. 시점을 명시해도 마찬가지다.
   - 역사적 사실처럼 고정된 사건은 필요하면 시점을 명시한다 (예: 1392년 조선 건국).
   - 지리적·분류적 범위를 한정한다 (예: 남한에서, 극지방을 제외하고).
4. 교차 검증했는가?
   - 의심스러운 정보는 2개 이상의 출처로 확인한다.
   - 논란이 있는 내용은 주류 학설을 기준으로 한다.
